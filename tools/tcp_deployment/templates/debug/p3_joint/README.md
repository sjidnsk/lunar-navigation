# P4/P3 Orin 现场联调配置

本目录保存 2026-09-16 已验证的现场配置，不是通用 TCP 直连默认配置。导出 P4 时放到 `debug/p3_joint`；不要直接在源码目录启动，以免运行产物写入源码。

## 环境与启动

部署位置 `/home/yanfa/P4`，ROS Humble，P3 融合域 57，旧车辆接口域 10。旧接口独占 `192.168.10.22:6668`，P4 此模式不启动自己的 TCP 客户端或虚拟地图。依赖现有 `/home/yanfa/Env_X/InterFace/install` 的消息、车辆接口和 GUI 租约支持；本包不包含或修改 P1/P2/P3。更换机器前需检查脚本、YAML 和 RViz 内的绝对路径、域和话题。

在上述环境且 P4 尚未运行时：

```bash
bash /home/yanfa/P4/debug/p3_joint/start_preview.sh
```

启动时应停车，反馈适配器会等待稳定位姿完成坐标锚定。脚本包含 RViz、探索器、导航器、控制器、反馈适配、私有 TF 输入和常驻转发；不会自动下发探索任务。RViz 用 2D Goal Pose 拖出目标朝向。已有 P4 运行时脚本会拒绝重复启动；不能重复启动来代替恢复任务。

- 旧接口继续独占 TCP；`legacy_feedback_input.py` 复用 P4 坐标转换和 PoseRates，生成 `/P4/input/odometry`，不发布车辆命令。

- 80% 与 99% 仅作为阶段指标；候选耗尽才结束，暂时抑制仍等待地图变化。详见 EXPLORATION_COMPLETION_POLICY.md。

## 已知操作限制

执行任务期间单独重启导航器，RViz 目标桥可能保留旧 Action 句柄而不再发送新目标；这时需一起重启 P4 目标桥。目前没有实现自动恢复源码修复。P3 定位原点或 Unreal 场景重置后，需要停车并重新启动反馈适配器完成锚定，不能继续使用旧锚定。

本目录只保存源码、配置、测试和说明；PID、锁、日志、标定快照、运行结果不随源码分发。测试记录中的设备运行结果属于当时环境，不代表任意设备部署即通过。

## 场景重置后的恢复边界

场景重置后先确认 P3 新位姿和地图有效，再停车重新建立 P4 对齐，并重启 P4 导航器与目标桥清除旧地图/任务状态，按新坐标系重建任务区域。不可把新 TCP 位置直接锚定到不再更新的旧 P3 位姿。当前没有自动检测场景重置和重新对齐的功能。

2026-09-16 后续重启现场出现 P3 配准持续不收敛，P4 等待有效输入。0.2 m 点云降采样只做过隔离对照测试，未修改在线参数；本模板不包含 P3 配准修复。恢复依赖 P3 正常定位，不能通过放宽控制器超时绕过。
