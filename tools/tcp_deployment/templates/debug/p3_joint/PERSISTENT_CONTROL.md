# P4 常驻车辆指令转发

2026-09-16，已在当前 Orin 联调环境启用。

## 日常操作

P4 启动一次后，在 RViz 使用 **2D Goal Pose**，点击目标位置并拖出终点朝向。
规划生成有效路径后自动接通旧车辆接口执行；到点后停车，但常驻转发不退出。
再次选目标即可执行下一次导航，无需重新启用转发，也不需要重启旧 TCP 接口或 P3。

当前转发进程：persistent_command_relay.py；启动脚本 start_preview.sh 已包含它。
正常无任务时 /P4/control/relay_status 为 PARKED；有可执行任务时为 FORWARDING。
状态快照：command-relay-status.json，进程记录：pids.json，日志：command-relay.log。
start_preview.sh 拒绝重复启动已在运行的 P4。此次未配置开机自启。

## 控制与停车

P4 域 57 的 /P4/debug/cmd_vel 经常驻进程转发至域 10 /car/cmd_vel。
速度始终由原 P4 控制器决定，转发进程不规划、不另算跟踪速度、不创建 TCP 连接。
旧 lunar_car_node 独占 192.168.10.22:6668。
沿用旧 GUI 的 /car/external_control_lease，常驻期间 GUI 持续速度发布让出控制权。

仅当前 ACTIVE 路径与同会话、同版本的跟踪反馈一致时允许转发。
无任务、完成、失败、等待或输入无效时发零速度并请求 park。
命令/跟踪状态/新里程计超过 0.5 秒，旧车辆遥测超过 1 秒均禁止运动。
保持当前 0.2 m/s、0.03 rad/s 上限；不放宽终点容差。
旧 GUI 的紧急停车仍可使用：外部 park 会阻止当前会话恢复运动，下一次明确下发的新目标才可重新启动。
若转发进程退出，发送零速度与 park 并释放 GUI 接管；异常终止时旧接口与 GUI 原有超时保护继续有效。
常驻期间不要运行旧一次性 motion_test/navigation_task/exploration_test 等转发脚本，已加冲突检查。
需要人工速度控制时，应先停止本 P4 常驻转发，让 GUI 恢复发布，不能让两者竞争。
