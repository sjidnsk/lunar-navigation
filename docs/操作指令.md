# Pure Planner 编译与节点启动指令

配置调整与重启生效说明见 [可调整运行配置](可调整运行配置.md)。

新增独立 Jazzy [复杂地形完整探索 demo](复杂地形完整探索demo.md)：300 m 复杂地形、全局 1 m / 局部 0.2 m、正式探索规划控制、默认 30 倍可调仿真时钟。[简单控制闭环 demo](增量规划控制闭环demo.md)及旧演示保留。

本文面向当前仓库：`/home/kai/CodexDownloads/lunar_navigation/lunar_pure_planner_orin`。命令分为四条互不混用的路径：

- **Humble 生产规划栈**：使用 `/Car/T3/*` 输入、`/Car/T4/*` 规划接口；可选启动轮式控制器。
- **Jazzy 月表 RViz 演示**：全部使用 `/lunar_demo/*`，不接入生产话题，也不控制车辆。
- **legacy 纯前沿探索节点**：调用已经运行的 legacy 生产规划 Action；不自动启动规划器、地图源或控制器。
- **incremental_v2 探索—导航栈**：只由局部 `GridMap`、odometry 和 `/tf` 累计建图；不读取全局先验图。

> 安全边界：`scripts/start_all.sh` 会启动 `lunar_pure_wheeled_controller`，其命令输出为 `/Car/T5/Car_Cmd_Vel`。仅在车辆控制链路获准且已具备急停/场地安全条件时使用。只做规划、RViz 或 Topic 验证时，请按“手动启动（不含控制器）”执行。

增量探索节点的 `navigation_map_wait_timeout_s` 默认 **30 秒**；显式设置 `0` 可关闭。使用仿真时间时按模拟秒计时。超时仅取消持续缺地图的当前导航，确认取消终态后再选择候选，不代表目标不可达。公共轮式配置的前进/后退上限均为 **0.2 m/s**。控制闭环仍需导航 `enable_tracking_feedback:=true` 与控制器 `input_mode:=incremental_reference` 配套启用。

### 直接发送月表目标

月表模式需同时具备全局总览与局部图：

```bash
ros2 action send_goal --feedback /Car/T4/plan_motion \
  lunar_planning_msgs/action/PlanMotion "{
  environment_mode: 1,
  request_id: surface-001,
  mission_id: manual,
  mission_revision: 0,
  goal: {
    header: {frame_id: map},
    goal_id: surface-goal,
    goal_type: 1,
    point: {x: 4.0, y: -2.0},
    position_tolerance_m: 0.25,
    has_yaw_constraint: true,
    yaw_rad: 0.0,
    yaw_tolerance_rad: 0.2
  },
  replace_active_request: false
}"
```

`Goal accepted` 或 Action CLI 的 `SUCCEEDED` 不能单独证明业务规划成功。读取结果时必须确认：

```bash
ros2 topic echo --once /Car/T4/planning/diagnostics
```

成功判据为 `planning_outcome: 0` 且 `has_reference: true`。无路径、输入缺失或安全约束拒绝时，系统应不发布有效参考；这是安全结果，不应以 Action 接收与否替代结果判定。

取消前台发送中的 Action：在运行 `ros2 action send_goal` 的**同一终端**按 `Ctrl+C`。替换现有请求时，发送新目标并设置 `replace_active_request: true`。

## 6.1 incremental_v2：增量地图、探索决策与导航会话

本节是独立于第 6 节 legacy 节点的新版入口。启动参数在启动前选择唯一栈，不能把两条栈并发到
同一 `/Car/T4/*` Topic，也没有自动回退：

```bash
export PROJECT_ROOT=/absolute/path/to/lunar_pure_planner_orin
cd "$PROJECT_ROOT"
source /opt/ros/humble/setup.bash
source "$PROJECT_ROOT/ros2_ws/install/setup.bash"

# 新版：唯一增量地图 + NavigateToPose 会话 + 薄探索决策。
ros2 launch lunar_pure_exploration_ros exploration_navigation.launch.py \
  stack_mode:=incremental_v2 platform_type:=wheel

# 明确回退：启动原有 pure planner + pure explorer，不改变其 ABI/行为。
ros2 launch lunar_pure_exploration_ros exploration_navigation.launch.py \
  stack_mode:=legacy platform_type:=wheel
```

若当前 install 尚未包含新增包，先在同一 Humble 目标环境构建依赖闭包后再 source；不要把 Jazzy
install overlay 用于 Humble/Orin：

```bash
cd "$PROJECT_ROOT/ros2_ws"
source /opt/ros/humble/setup.bash
colcon build --packages-up-to \
  lunar_incremental_navigation_ros lunar_pure_exploration_ros \
  lunar_pure_planner_ros
source install/setup.bash
```

`config/exploration_navigation.yaml` 由 `lunar_pure_exploration_ros` 安装，集中提供 `incremental_v2` 的
`stack.mode`、`platform_type`、Topic、`coarse_resolution_m`（默认 `1.0 m`）、
`navigation.local_window_size_m`（默认 `64.0 m`）和探索参数。
轮式净空代价默认权重为 `2.0`；如需覆盖默认值，可在 YAML 的 `navigation` 下添加
`clearance_weight: 2.0`（`0.0` 用于关闭对照）。该参数必须为有限非负值，修改后重启节点生效。
足式默认权重保持 `0.0`。权重不改变可通行栅格或硬膨胀半径，详见
[净空权重实验](validation/2026-09-19-clearance-cost-calibration.md)。
`config/incremental_navigation_interfaces.yaml` 记录新版接口类型与默认 QoS。显式
`stack_mode:=legacy` 不读取该 YAML，也不要求 `lunar_incremental_navigation_ros` 已安装；只使用 legacy
launch 自己的默认值及显式 `platform_type`/`use_sim_time`。不要通过 launch 参数混入全局图、current pose、
额外地图或运行时分辨率切换。

### 输入、地图和检查

incremental_v2 的环境输入只有下表；第 2 节的 `global_overview` 要求属于 legacy 月表规划，**不适用于本节**。

| Topic | 类型 | 订阅者与用途 |
| --- | --- | --- |
| `/Car/T3/mapping/grid_map` | `grid_map_msgs/msg/GridMap`（`elevation` layer） | 只由 `incremental_navigation` 订阅，增量构建唯一地图。 |
| `/Car/T3/localization/odometry` | `nav_msgs/msg/Odometry`，`odom -> base_link` | 导航器与探索器的状态输入。 |
| `/tf` | `tf2_msgs/msg/TFMessage` | 直接 `map -> odom` 变换。 |

默认位姿契约为 `odom -> base_link`；增量栈可通过 `common.frames` 同步调整三个帧名称，仍要求直接 map 到 odom 的 TF。`config/wheel.yaml` 的
`base_frame_id: base_footprint` 仍只表示轮式 footprint 几何，不改变此 Topic/TF 契约。

第一张有效 `GridMap` 决定 fine resolution：当前 `0.2 m` 和未来 `0.1 m` 都直接按输入保持。`0.1 m`
不会重采样为 `0.2 m`；改变分辨率要重启整个 incremental_v2 栈。轮式与足式仍使用既定的可通行性和
8 邻域 A*，本接线不改变算法。`local_window_size_m=64.0` 时，局部规划窗口为 `0.2 m -> 320 × 320`
和 `0.1 m -> 640 × 640`；若按当前 fine resolution 需要超过 `640` 格/轴，周期返回
`LOCAL_WINDOW_CAPACITY_EXCEEDED`，不会静默缩小物理窗口。

导航器从同一 fine snapshot 发布正式探索图：
`/Car/T4/mapping/exploration_map`，类型 `nav_msgs/msg/OccupancyGrid`，取值固定为
`-1=UNKNOWN`、`0=FREE/CANDIDATE`、`100=PROVEN_BLOCKED`，QoS 为 Reliable + Transient Local +
KeepLast(1)。探索器只读它，不订阅原始 `GridMap`，不拥有第二个 `PersistentElevationMap`；导航器也不
订阅任务 Topic。新版探索器只接受这三个精确值，其他值发布为 `INVALID_EXPLORATION_MAP`，不会提交
goal。任务仍按第 6 节格式发布到 `/Car/T4/exploration/task`，探索器一次只维护一个
`NavigateToPose` goal。

启动后先做只读检查：

```bash
ros2 topic info -v /Car/T3/mapping/grid_map
ros2 topic info -v /Car/T4/mapping/exploration_map
ros2 topic info -v /Car/T4/planning/local_path
ros2 action info /Car/T4/navigation/navigate_to_pose
ros2 node info /incremental_navigation
ros2 node info /incremental_exploration
```

预期第一条只有导航器订阅；第二条由导航器发布、探索器订阅；`/Car/T4/planning/local_path` 为导航器发布的
`nav_msgs/msg/Path`，QoS 为 Reliable + Transient Local + KeepLast(1)；Action 为探索器 client、导航器 server。
`/Car/T3/mapping/global_overview` 与 `/Car/T3/semantic/current_pose` 不应成为本栈订阅。

### 结果判定和 RViz

规划周期成功必须在 `/Car/T4/planning/diagnostics` 中满足 `cycle_result=PLAN_FOUND`，同时
`/Car/T4/planning/path_reference` 是非空 `ACTIVE` 路径且其 segment/traversability revision 与诊断一致。
目标导航成功只以 `NavigateToPose` Action Result 的 `GOAL_REACHED` 为准；Action accepted、RViz 线条或
单独的 PathReference 都不等价于完成。

`/Car/T4/planning/local_path` 专供只跟踪局部路径的控制器：非空消息可直接跟踪，空消息表示清空当前
跟踪目标。控制器不需要解析 `/Car/T4/planning/path_reference` 的 session、state 或 revision。该 `Path`
不携带线速度、角速度或逐点执行时间；控制器按自身控制参数和实时 odometry 生成 `Twist`。不要把
`/Car/T4/planning/global_route` 用作控制输入。

### 显式启动轮式局部路径控制器

该控制器不由 `exploration_navigation.launch.py` 自动启动。执行前必须先完成获授权的车辆控制与急停流程，
并确认运行期间它是 `/Car/T5/Car_Cmd_Vel` 的唯一命令发布者；所有 teleop 或其他控制器必须停止。然后在
已 source 相同 ROS overlay 的独立终端执行：

```bash
ros2 launch lunar_pure_wheeled_controller pure_wheeled_controller.launch.py \
  input_mode:=incremental_path \
  path_topic:=/Car/T4/planning/local_path \
  odometry_topic:=/Car/T3/localization/odometry \
  tf_topic:=/tf
```

该模式只接受 `map` frame 的非空局部路径，并读取 `/tf` 中直接的 `map ← odom` 变换（`header.frame_id=map`、
`child_frame_id=odom`）将实时 odometry 转到 `map`。它不遍历 TF 图、不做时间同步或历史变换。空路径或非法

已有 `resume.pt` 时必须 `--resume` 或改用新输出子目录。

默认预热 1024 条，之后每新增 4 条有效转移挣得一次更新额度；有效 batch 64、microbatch 16，
Critic→Actor→温度→目标软更新各一次。每 16 次学习更新发布 Actor，保存的是实际已发布权重，
可能落后 learner 至多 15 次。`transitions` 是累计有效采集数；`new_transitions`/有限进度条只计本次新增，
有界停止可因保留已完成转移小幅超额。`credit`、`inflight`、`replay_count`、`actor_version`、
每槽状态/原因、`save_in_s` 解释调度进展；预算截断、零收益或规划失败不表示探索完成。
没有无限训练的虚构总完成百分比。

以下是可复制的功能探针，先选择从未使用的输出目录；它保持默认网络和物理参数，
显式仅改小图、预算、预热和本次长度，不是正式训练配置：

```bash
scripts/drl/train.sh --probe --probe-warmup 64 --probe-extent 40 --probe-budget 8 \
  --max-transitions 160 --output-dir training-output/drl-exploration-redesign/my-new-probe
scripts/drl/train.sh --resume --probe --probe-warmup 64 --probe-extent 40 --probe-budget 8 \
  --max-transitions 64 --output-dir training-output/drl-exploration-redesign/my-new-probe
```

恢复探针重复相同语义设置，`--max-transitions 64` 意味着**再采 64 条**。
默认环境 DDS 域 210–217，命名空间 `/lunar_training/env_0` 至 `_7`，
可用 `--domain-base` 指定空闲连续域；不会使用车辆控制话题。
采集进度同时显示实际动作 RTF；30 是目标，不保证达到。物理积分仍为 0.05 仿真秒，
观测 2 Hz、10 m/90°，最高速度 0.2 m/s。主课程为 40–80/80–150/100–300 m、
512/2048/8192 决策预算；累计 0–19999 全小图、20000–59999 小/中 25/75%、
60000 起小/中/大 15/25/60%，每槽下个回合才换课程，月表/洞穴固定 4+4。

### 导出与冻结评估

```bash
scripts/drl/_run.sh export \
  --checkpoint training-output/drl-metric-critic/resume.pt \
  --output training-output/drl-metric-critic/actor.pt
scripts/drl/evaluate.sh --actor training-output/drl-metric-critic/actor.pt \
  --seeds 2026091501 2026091502 --families moon cave --extents 40 100 --budget 512 \
  --output training-output/drl-metric-critic/evaluation.json
```

导出是 `task_graph_v3` Actor-only schema，评估使用联合 argmax，无 learner/replay 更新。
评估种子是 `[0, 2^32)`，训练场景种子属于更高命名空间。逐案例保留 80/99 达成、
耗尽、最终参考覆盖、到阈值及 80→99 路程、零收益、截断、导航失败、碰撞和基础设施错误；
逐案例 `covered_area_m2` 是与参考相交的已覆盖面积，`coverable_area_m2` 是初始化参考分母；
初始化失败两者为 null，执行失败保留最后确认值，空参考面积和比例均为 0。报告保存全部有效传感器配置（含安装偏移）。
未达到阈值的距离为 null，不能丢弃失败案例。`--sensor-range`/`--sensor-fov` 可改变冻结评估观测，
只证明接口可配置，泛化能力须另外训练/评估。输出报告和显式 Actor 也计入磁盘预算。
安装的 `lunar-drl` console 脚本使用同一 CLI；成功动作退出 0，Python `cli.main(argv)` 保留结果对象。

### 部署推理与唯一目标所有权

`infer` 仅挂接现有实测地图、导航和控制器，不启动整套系统。部署时学习策略是
**唯一探索目标来源**；传统 `incremental_exploration_node` / legacy 前沿探索节点不应同时运行。
不要用会同时启动传统探索器的 `launch/exploration_navigation.launch.py` 来补齐 infer 依赖。

对于已具备真实/回放地图、odometry 与 map→odom TF 的专用环境，分别在干净终端加载相同 overlay：

```bash
env -u AMENT_PREFIX_PATH -u COLCON_PREFIX_PATH -u CMAKE_PREFIX_PATH \
  -u ROS_PACKAGE_PATH -u PYTHONPATH -u LD_LIBRARY_PATH \
  bash --noprofile --norc
source /opt/ros/jazzy/setup.bash
source /home/kai/.cache/lunar-drl-redesign/jazzy/install/local_setup.bash
cd /home/kai/WS/lunar-navigation/lunar-runtime/.worktrees/drl-exploration-redesign
```

导航终端（若已有相同节点则复用，不重复启动）：

```bash
ros2 run lunar_incremental_navigation_ros lunar_incremental_navigation_node --ros-args \
  -p platform_type:=wheel -p platform_config:="$PWD/config/wheel.yaml" \
  -p goal_position_tolerance_m:=0.05 -p goal_yaw_tolerance_rad:=0.2617993877991494
```

控制器终端（同样复用已存在的唯一公共控制器）：

```bash
ros2 run lunar_pure_wheeled_controller lunar_pure_wheeled_controller_node.py --ros-args \
  -p input_mode:=incremental_reference -p platform_config:="$PWD/config/wheel.yaml" \
  -p goal_position_tolerance_m:=0.05 -p goal_yaw_tolerance_rad:=0.2617993877991494
```

这些默认接口会连接 `/Car/...`，属于目标环境操作示例，本轮没有执行实车部署。
地图生产者负责 `/Car/T3/mapping/grid_map` 的分类输入；导航拥有
`/Car/T4/mapping/get_policy_map`、`/Car/T4/navigation/navigate_to_pose` 及
`/Car/T4/planning/path_reference`；控制器独占 `/Car/T5/Car_Cmd_Vel` 并反馈
`/Car/T4/control/tracking_status`。状态来自 `/Car/T3/localization/odometry` 和 `/tf`，
地图 QoS 必须匹配现有生产者（导航默认 reliable/transient_local；按实际源参数调整）。
导航和控制器 DRL 到位精度都为 0.05 m，yaw 都为 π/12；传统默认值不修改。
仿真/回放使用时各节点须统一时钟配置，不能把本节当成已经验证的真实传感器配置。

推理终端：

```bash
scripts/drl/infer.sh --actor training-output/drl-metric-critic/actor.pt \
  --config config/drl_exploration.yaml --task-topic /Car/T4/exploration/task
```

任务接口为 `lunar_pure_exploration_msgs/msg/PureExplorationTask`，
`command` START=1、PAUSE=2、RESUME=3、CANCEL=4，START 提供 map frame 下的任务多边形。
状态在 `/Car/T4/exploration/drl_status`，只报告实测累计已知面积、输入可用性和耗尽；
无真值参考面积时不虚构部署覆盖率。任务外目标/路径仍合法，任务外运动照常计代价。
可只读核对接口：


真实课题三传感器、跨主机 DDS 和实车验收；当前短程未训练策略探针也不证明 80/99、耗尽、收敛或泛化。
