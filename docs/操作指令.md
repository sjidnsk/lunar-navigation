# Pure Planner 编译与节点启动指令

本文面向当前仓库：`/home/kai/CodexDownloads/lunar_navigation/lunar_pure_planner_orin`。命令分为三条互不混用的路径：

- **Humble 生产规划栈**：使用 `/Car/T3/*` 输入、`/Car/T4/*` 规划接口；可选启动轮式控制器。
- **Jazzy 月表 RViz 演示**：全部使用 `/lunar_demo/*`，不接入生产话题，也不控制车辆。
- **纯前沿探索节点**：调用已经运行的生产规划 Action；不自动启动规划器、地图源或控制器。

> 安全边界：`scripts/start_all.sh` 会启动 `lunar_pure_wheeled_controller`，其命令输出为 `/Car/T5/Car_Cmd_Vel`。仅在车辆控制链路获准且已具备急停/场地安全条件时使用。只做规划、RViz 或 Topic 验证时，请按“手动启动（不含控制器）”执行。

## 0. 前置条件

生产栈运行在 Ubuntu 22.04 + ROS 2 Humble。每个新终端都必须重新 source 环境；不要混用 Humble 与 Jazzy 的 overlay。

```bash

cd "$PROJECT_ROOT"
source /opt/ros/humble/setup.bash
```

生产规划器本身不生产以下输入，须由课题三节点、仿真或 rosbag 提供：

| 输入                              | 用途                                       |
| --------------------------------- | ------------------------------------------ |
| `/Car/T3/mapping/global_overview` | 月表全局占据图（仅 `environment_mode: 1`） |

## 2. Humble：先确认外部输入

在启动本包节点前，先在一个已 source 的终端检查外部发布者。以下命令只读，不会发送控制命令：

```bash
ros2 topic list | grep -E '^/Car/T3/(mapping/global_overview|mapping/grid_map|localization/odometry)$|^/tf$'
ros2 topic info -v /Car/T3/mapping/grid_map
timeout 5 ros2 topic echo --once /Car/T3/mapping/grid_map
timeout 5 ros2 topic echo --once /Car/T3/localization/odometry
```

若地图来自缓存型发布者，建议在局部可通行性节点已启动后重新发布一次，或从 rosbag 开头重放。默认输入 QoS 是 `reliable + transient_local`；若 `ros2 topic info -v` 显示上游是 `best_effort + volatile`，启动局部可通行性时需要使用第 3 节给出的 QoS 覆盖。

## 4. Humble：启动完整轮式规划/控制栈

确认第 0 节的外部输入已可用、车辆控制已获准后，在仓库根目录运行：

`2` 是熔岩洞 `environment_mode`。月表模式使用 `1`：


停止：在运行 `start_all.sh` 的终端按 `Ctrl+C`。手动启动的各节点则分别在所属终端按 `Ctrl+C`。

## 5. Humble：发送规划目标与判定结果

### 交互式熔岩洞目标

完整栈或第 3 节的规划器已运行后：

```bash
export PROJECT_ROOT=/home/kai/CodexDownloads/lunar_navigation/lunar_pure_planner_orin
cd "$PROJECT_ROOT"
bash scripts/send_goal.sh
```

按提示输入 `odom` 坐标系下的 `x`、`y` 和可选 yaw。选择一次性“完全信任桥接”会设置 `/pure_planner` 的 `trusted_bridge_once` 参数；它仅适用于下一条被接受的熔岩洞轮式请求，且桥接段不做地图/障碍/坡度检查。

### 直接发送月表目标

月表模式需同时具备全局总览与局部图：

```bash
ros2 action send_goal --feedback /Car/T4/plan_motion \
  lunar_planning_msgs/action/PlanMotion "{
  environment_mode: 1,
  request_id: surface-001,
  mission_id: manual,
  mission_revision: 0,
  goal: {
    header: {frame_id: map},
    goal_id: surface-goal,
    goal_type: 1,
    point: {x: 4.0, y: -2.0},
    position_tolerance_m: 0.25,
    has_yaw_constraint: true,
    yaw_rad: 0.0,
    yaw_tolerance_rad: 0.2
  },
  replace_active_request: false
}"
```

`Goal accepted` 或 Action CLI 的 `SUCCEEDED` 不能单独证明业务规划成功。读取结果时必须确认：

```bash
ros2 topic echo --once /Car/T4/planning/diagnostics
```

成功判据为 `planning_outcome: 0` 且 `has_reference: true`。无路径、输入缺失或安全约束拒绝时，系统应不发布有效参考；这是安全结果，不应以 Action 接收与否替代结果判定。

取消前台发送中的 Action：在运行 `ros2 action send_goal` 的**同一终端**按 `Ctrl+C`。替换现有请求时，发送新目标并设置 `replace_active_request: true`。

## 7. Jazzy：本机月表 RViz 演示（测试专用）

这条路径只能使用 Jazzy，并与第 1～6 节的 Humble 生产栈隔离。它会生成 `/lunar_demo/*` 的合成 `1 km × 1 km` 全局地图（`1000 × 1000`、`1 m/cell`），并向规划器提供以车为中心的 `64 m × 64 m` 局部 GridMap（`320 × 320`、`0.2 m/cell`）、里程计和 Action，**不会**消费 `/Car/T3/*` rosbag，也不包含控制器。

```bash
export PROJECT_ROOT=/home/kai/WS/lunar-navigation/lunar-runtime/.worktrees/wheel-legged-demo-delivery-closed-loop
cd "$PROJECT_ROOT"
source /opt/ros/jazzy/setup.bash

colcon build --base-paths ros2_ws/src \
  --build-base build-jazzy-demo-delivery \
  --install-base install-jazzy-demo-delivery \
  --packages-up-to lunar_pure_planner_ros \
  --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo
source install-jazzy-demo-delivery/setup.bash

# 轮式
ros2 launch lunar_pure_planner_ros lunar_surface_rviz_demo.launch.py \
  platform_type:=wheel

# 足式另开一次进程；不要与轮式实例同时启动
ros2 launch lunar_pure_planner_ros lunar_surface_rviz_demo.launch.py \
  platform_type:=legged
```

该测试 launch 显式启用 Demo 交付协议，生产默认关闭。新目标到达后，Demo 先停车并清除旧执行段。
首个目标或恢复 STOP 使用同 token 交付全局图、局部图、odometry 和 `map->odom` TF；后续 4 m 滚动周期
只重交付局部图和当前位姿 odometry。规划器只有在输入身份一致、起点处于局部窗口内，且平台输入
已就绪后才发布 ACK；同 token 重发不重建输入序列或足式投影。Demo 只执行匹配当前
`request_id + map_token + segment_index` 的 EXECUTE 信封，普通 `Path` 只供 RViz 显示。轮式与足式
均按 `12 m` 名义前视规划，每移动 `4 m` 生成新 token；ACK 前只短暂保持交付快照，ACK 后继续执行
旧段并在后台等待下一段，新段从当前位置附近的前向路径接续。仅当旧段耗尽、新目标、恢复或失败
时停车。
该隔离 Demo 的 ACK 窗口为 `10 s`，生产默认参数不变。Reporter 的 `local=` 来自已授权 EXECUTE 路径，
不再把轮式全局 preview 误报为局部执行段。

滚动模式默认允许成功段之后的局部 `NO_PATH`/`TIMEOUT` 最多恢复两次。恢复诊断包含
`rolling_recovery=true` 和 `rolling_recovery_attempt=N`，并先发布空路径使 Demo 停止旧路径；
首次失败、不可恢复错误或次数耗尽仍终止 Action。这里没有放宽输入身份检查，也没有延长每周期
`3 s` 硬截止。

在 RViz 中将 Fixed Frame 设为 `map`，初始顶视范围约为整张地图；粉紫色圆盘和 `Current rover position` 标签标记车辆当前位置。等待约 6 秒让百万格输入进入规划器，再用 **2D Goal Pose** 选择空白可达区域。预期 `/lunar_demo/path` 更新，并与轮式可通行性和采样高程同屏展示。为避开部分 Mesa/RViz 的 GLSL sampler 冲突，默认关闭原始 OccupancyGrid Display；轮式可通行性图仍显示障碍与安全判定。点击障碍物或不可达点时没有有效路径是预期的安全行为。验证命令：

```bash

ros2 topic echo --once /lunar_demo/path
ros2 topic echo --once /lunar_demo/traversability
```

`reason_code: PLAN_FOUND`。`PLAN_FOUND_LATE`、Action `SUCCEEDED` 或仅出现 RViz 路径都不能单独作为
正式成功证据。一次中间成功也不代表整条滚动 Action 已经完成；最终还需 Action 正常完成且
odometry 进入目标容差。

## 8. 常见故障定位

| 现象                               | 先执行                                                                                                     | 处理方向                                                                    |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `Package ... not found`            | `echo "$AMENT_PREFIX_PATH"`; `ls "$PROJECT_ROOT/ros2_ws/install/setup.bash"`                               | 先 source `/opt/ros/humble/setup.bash`，再构建并 source overlay。           |
| `start_all.sh` 报 overlay 不存在   | `ls "$PROJECT_ROOT/ros2_ws/install/setup.bash"`                                                            | 在 `ros2_ws` 运行第 1 节构建命令。                                          |
| Action 未出现                      | `ros2 node list`; `ros2 action list`                                                                       | 检查规划器终端日志与 Humble/overlay 是否来自同一工作区。                    |
| 局部可通行性没有数据               | `ros2 topic info -v /Car/T3/mapping/grid_map`; `timeout 5 ros2 topic echo --once /Car/T3/mapping/grid_map` | 对齐 QoS；让上游在节点启动后重发或从 bag 起点回放。                         |
| RViz 有原始地图、无 traversability | `ros2 topic info -v /Car/T4/planning/local_traversability`                                                 | 先确认输出样本，再检查 RViz 的 GridMap 插件、图层 `traversability` 与 QoS。 |
| `SUCCEEDED` 但没有可执行路线       | `ros2 topic echo --once /Car/T4/planning/diagnostics`                                                      | 以 `planning_outcome: 0` 与 `has_reference: true` 为准，检查诊断原因码。    |

## 9. 最小验证清单

生产栈只应在每项通过后进入下一项：

1. `colcon build` 成功，且 overlay 存在。
2. 外部 `grid_map`、odometry 和 `/tf` 有实际样本；月表另有 `global_overview`。
3. `/local_traversability`、`/pure_planner` 和 `/Car/T4/plan_motion` 出现。
4. `local_traversability` 有实际消息，不只是在 topic list 中可见。
5. Action 结果对应的诊断同时满足 `planning_outcome: 0`、`has_reference: true`。
6. 只有在需要车辆执行且安全条件满足时，才启动控制器并观察 `/Car/T5/Car_Cmd_Vel`。
