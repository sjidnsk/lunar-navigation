# 配对实验碰撞原因复核

## 已确认的结论

导航器、公共跟踪器和运动学碰撞判定未因有界 Actor 对照修改。与 `training-output/actor-bounded-20260919/before.json` 的源码哈希对照，相关导航、控制、环境和平台文件共 148 个均一致；导航核心、ROS 导航、公共控制器、`plant.py` 相对当前 HEAD 无修改。`ros_env.py` 在前一轮决策图/Critic 实施中仅改真值描述构建及释放，不改运动执行或碰撞分支。

新决策图改变了送入导航的目标和路径序列。旧 `drl-valid-actions-small` 保留的 1611 条转移均为 GOAL_REACHED，实际行驶距离中位数 0.1908 m；当前 raw 首轮保留的 1411 条转移中位数 2.195 m，其中 7 条 COLLISION。两批不是同场景配对样本，不能据此算改动的因果碰撞增幅；但足以说明同一执行栈收到了不同运动任务。C=0 原始分数组也碰撞，不能归因于新增 tanh 变换。

当前 `COLLISION` 表示 `KinematicPlant._swept` 拒绝真实位姿积分的候选段：终点必须属于真值导航 M 的 FREE 格，对角跨格还检查两侧格。M 已考虑平台包络；这不是完整车体动力学接触仿真。它不能直接等同于已经发生物理车体撞墙，也不能被当成无关紧要的误报。

## 补充：训练控制器不等于 TCP 验证版本

旧 OBJ/TCP 分支引用 `af5feef0` 的公共控制器 tree 为 `c603be04e4135b1680f30d12a5d356bb8d1cdfd0`，与当前保留分支 `app/orin-unreal-simulation` 的公共控制器 tree 相同。该分支工作树的控制器与仿真配置没有未提交修改。当前 DRL 已安装的 execution/tracking/node/frame 四文件与 DRL 源码一致，但与 TCP 版均不同。

两者都是公共 `PathExecutor`、纯追踪与 BRAKING/ALIGNING/TRACKING/FINAL_ALIGN 状态机，输入模式都是 `incremental_reference`。实质差异：

- TCP 版基于上一条实际发送的 v/ω 指令限制变化率；DRL 版基于测量速度。TCP 修正针对反馈滞后/波动造成的反复减速及停转困难。
- TCP 节点每次发指令（包括强制零指令）回写执行器命令历史；DRL 没有该接口。
- TCP 停车判据包含平面横向速度；DRL 只看前后速度和角速度。
- TCP 历史配置 `af5feef0`：角速度上限0.15 rad/s、角加速度0.1 rad/s²；DRL 启动配置：1.0 rad/s、0.5 rad/s²。TCP 保留分支现在角速度改为0.1 rad/s；这不是当前进程生效参数的现场证明。
- TCP 到位位置容差0.1 m，DRL 为0.05 m。TCP 使用转向轮对齐后才放行轮速的车辆适配；DRL 是带加速度限制的轻量运动学平台，未模拟轮子转向准备过程。

因此此前“导航/控制未改变”的结论仅适用于 DRL 这轮改动前后，不能扩展为“与 TCP 验证版本完全一致”。TCP 改进值得在相同路径、相同参数下单独对照；尚未证明移植该版本就能消除已知贴边碰撞。节点位置和执行器版本是两个需要分离验证的因素。
