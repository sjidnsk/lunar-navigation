# 可调整运行配置

本次修改位于 `fix/flexible-runtime-config`，基于集成主线 `56729a7`。默认速度、地图分辨率、候选朝向及接口名称保持原值。修改配置后重启生效；不是运行中自动更新规划器、地图和控制策略。

## 可以调整什么

| 配置 | 当前行为 |
| --- | --- |
| `config/wheel.yaml`、`legged.yaml` 等能力数值 | 移除两套规划器的整份固定数值比较。仍检查字段、有限数值、正负范围、平台种类以及运动原语方向、唯一 ID 等有效性。 |
| `capability_version`、`platform_id`、几何 `base_frame_id` | 非空标识，不再必须与示例配置的字符串相等。它们不是消息协议版本协商。 |
| 运动原语列表 | 非空列表，不再要求轮式恰好 9 项、足式恰好 6 项；原语集合会影响搜索能力。 |
| `exploration.yaw_offsets_deg` | 有限且严格递增的非空列表，例如 3 项或 7 项；总候选预算仍由 `maximum_candidate_views` 限制。 |
| `sensor_range_m`、`sensor_fov_deg` | 范围为正，视场在 `(0, 360]` 度内；与真实传感器能力一致的配置由部署者提供。 |
| `common.frames` | 增量导航、探索支持自定义 map/odom/base 名称，实际输入变换和输出帧一起传递。 |
| `common.local_map_qos`、`exploration_map_qos` | reliability 支持 `reliable` / `best_effort`；durability 支持 `transient_local` / `volatile`；history 支持 `keep_last`，depth 为正整数，缺省 1。 |

平台能力 YAML 仍由导航器、探索器分别读取适合本模块的类型。取消固定值比较不等于支持任意字段或任意物理模型；未知字段、错误平台类型和不支持的算法语义仍会报错。轮式 footprint 目前仍使用四顶点配置结构。

## 修改临时配置的操作

从仓库根目录复制配置到仓库外，编辑自己的副本：

```bash
mkdir -p /tmp/lunar-custom-profile
cp config/wheel.yaml /tmp/lunar-custom-profile/wheel.yaml
cp config/exploration_navigation.yaml /tmp/lunar-custom-profile/exploration_navigation.yaml
```

在副本 `exploration_navigation.yaml` 的现有 `common` 中加入：

```yaml
  platform_config: /tmp/lunar-custom-profile/wheel.yaml
```

统一 launch 将此路径同时交给导航和探索。未设置时使用所选平台的安装配置。在现有 `exploration` 中可以改为：

```yaml
  yaw_offsets_deg: [-45.0, 0.0, 45.0]
  sensor_range_m: 12.0
```

能力文件中可以把 `maximum_forward_speed_mps` 和 `maximum_reverse_speed_mps` 改为 `0.1`。完成构建并 source 本分支安装目录后，通过配置文件启动：

```bash
ros2 launch lunar_pure_exploration_ros exploration_navigation.launch.py \
  config_file:=/tmp/lunar-custom-profile/exploration_navigation.yaml
```

该命令只启动导航和探索，需要外部地图、定位、TF 和探索任务；不会启动控制器。控制器单独运行时也应传入同一 `platform_config`。控制器有效约束取自身参数与能力文件中的较小值：只调大规划能力文件，并不会自动调大控制器自身限速。

## 坐标系和 QoS 的实际约束

`common.frames: {map: world, odom: local_odom, base_link: robot_base}` 表示：

- 输入高程图位于 `local_odom`，里程计表达 `local_odom -> robot_base`。
- `/tf` 提供直接 `world -> local_odom` 变换。当前实现不负责查找任意多跳 TF 链。
- 导航目标、探索任务边界、规划输出及地图使用 `world`。
- 单独启动的增量控制器应设置 `map_frame:=world`、`odom_frame:=local_odom`、`base_frame:=robot_base`。

这里改变的是整条增量链的名称和变换匹配，不是直接给旧坐标数据换标签。能力文件中的 `base_frame_id` 是几何元数据，不能代替里程计 child_frame。

统一配置的探索图 QoS 同时传给导航发布端与探索订阅端。局部高程图由外部系统发布，需要按外部发布端配置：例如 BestEffort/Volatile 发布者需要使用兼容的订阅参数。选择 Volatile 后，新订阅者不能依赖历史地图消息。这次没有将所有状态、Action、控制话题 QoS 全部改成动态可配。

## 启动配置与在线修改

增量导航、增量探索和轮式控制器对已声明、需要重启的参数，在运行中收到不同值时返回失败，说明具体参数名与 `restart`；原值保留。重复设置相同值允许，ROS 自带 `use_sim_time` 仍由 ROS 处理。

因此尺寸变化会在重启后重新建图，速度变化会在重启后重建控制策略。尚未实现在线修改尺寸时重算已有通行性、重认证正在执行路径等事务。旧 legacy 节点本次只涉及能力加载和朝向集合，不提供完整的自定义坐标系链或新的在线更新机制。

加载器保留机器可读 `PLANNER_ERROR`，同时附带配置路径和具体字段原因；例如负数 `maximum_forward_speed_mps` 明确报告必须大于零。没有通过降低路径认证标准来放开配置。

探索包原有的三个 legacy 源文件 SHA256 相等检查已移除；实际编译和兼容性测试继续保留，避免任何正常源码修改都会被哈希门槛拒绝。
