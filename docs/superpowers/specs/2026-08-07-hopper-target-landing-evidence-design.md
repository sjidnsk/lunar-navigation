# 飞跃式目标着陆证据窗与有限高度越障设计

> **现行修订（2026-08-08）：** 目标中心 L0 证据窗、有限高度越障、单次抛物线和飞行管语义
> 继续有效；文中的“剩余燃料”和“燃料认证”统一解释为不递减的固定单跳 Δv 包络，不存在跨
> Goal 库存。现行解释见 `2026-08-08-formal-capability-and-hopper-no-fuel-budget-design.md`。

## 1. 目标

飞跃式平台保持“静止起飞、一次抛物线、精确目标、输出安全凸着陆区域”的既定能力边界，修正
当前 RViz 合成地图流程中 `local_map` 随平台当前位置移动所造成的隐含距离限制：飞跃式
`local_map` 必须覆盖目标着陆区域，而不是覆盖整段飞行距离或只覆盖起点周围。

普通月岩、坡面和其他具有有限高度的障碍不构成无限高二维墙。只要完整三维飞行管能证明从
障碍顶面上方通过，规划器就允许越障；目标支撑区域本身仍不得包含障碍。

## 2. 不变边界

- 不增加多跳搜索、着陆节点图或局部路径搜索。
- 不修改平台质量、比冲、燃料、支撑半径、飞行管半径及其他正式能力数值。
- 不修改 `PlanMotion` Action、`GridMap` 消息或现有环境地图 Topic 名称。
- 轮式和足式继续使用平台中心 L0 局部窗口。
- 飞跃式继续只输出一条经过燃料和飞行管认证的名义抛物线。
- 外部地图生产方仍拥有 L0 数据；规划器不得由粗全局图虚构高分辨率着陆证据。
- `forbidden` 暂时保持绝对禁入/禁飞语义，不能用普通有限高度障碍代替；若以后需要区分
  “禁止着陆但允许上空通过”和“禁止进入空域”，必须另行冻结独立语义层。

## 3. 已评估方案

### 3.1 方案 A：目标中心 L0 着陆证据窗（采用）

地图生产方在发送飞跃式规划 Action 前，把 `local_map` 移到精确目标或上游给定着陆凸区域
附近。窗口仅需完整覆盖：

```text
landing_support_radius
+ landing_lateral_margin
+ 地图/定位不确定性裕量
+ 至少一个用于生成正面积凸区域的 L0 外扩带
```

优点是语义正确、计算量与着陆支撑区域相关且不随跳跃距离增加；同一规则可用于 10 m、
100 m 或更远目标。缺点是地图生产方与 Action 发送方必须完成一次确定的目标窗同步。

### 3.2 方案 B：从全局图直接认证落区（不采用为通用方案）

当 50 m 合成地图的全局图恰好也是 L0 时，理论上可以直接从全局图认证目标。但多分辨率地图
中的全局图可能是 L1-L4，无法满足支撑圆、坡面和平面残差的 L0 证据要求。把这种偶然条件写入
核心会掩盖真实系统缺少目标局部观测的问题。

### 3.3 方案 C：扩大起点中心窗口覆盖最大跳距（拒绝）

该方案让内存和处理量随跳跃距离平方增长，并把地图窗口大小再次变成隐式运动能力上限；不符合
“窗口大小由着陆认证需要决定”的规则。

## 4. 正式数据流

### 4.1 核心规划器

核心继续执行以下顺序：

1. 将 `goal_map` 变换到 `local_map` 的 `odom` 坐标系。
2. 在 L0 `local_map` 中检查以精确目标为中心的完整支撑圆，验证有效性、观测新鲜度、障碍、
   禁区、坡度和平面拟合残差，生成正面积凸着陆区域。
3. 把认证落区变换回 `map`。
4. 根据静止起飞、月面重力、质量、比冲和剩余燃料求解候选抛物线。
5. 使用 `global_map` 对完整飞行管执行三维碰撞认证。

核心不要求 `local_map` 的几何中心与目标精确相等，只要求目标支撑圆及凸区域外扩证据完整落在
同一个新鲜 L0 快照中。这样真实地图系统可以根据传感器可见范围适当偏置窗口。

### 4.2 RViz 合成地图桥

当前外部 RViz 仓的合成地图保存完整 L0 数据，因此可以从冻结 L0 数据切出目标窗口。同步流程为：

1. RViz `/goal_pose` 到达交互控制器并通过既有目标格式校验。
2. 飞跃式控制器通过 ROS 2 参数服务原子设置桥接器的目标 `x/y`；轮式和足式不执行此步。
3. 桥接器只在两个坐标同时存在、均为有限值、目标窗口能从 L0 数据切出且仍包含目标点时接受
   更新；失败时不替换旧窗口。完整支撑圆是否被覆盖仍由核心规划器按正式能力值检查。
4. 控制器调用既有 `/lunar_isaac_validation/ready`。桥接器使用新窗口连续发布同一时间戳的
   `global_map`、`local_map`、里程计、TF、任务和燃料状态，并等待既有 DDS settle 周期。
5. `ready` 返回的新时间戳写入 Action Goal，随后才发送 `PlanMotion`。

参数服务只是外部 RViz 测试桥的控制面，不改变正式地图 Topic 或 Action 接口。真实系统应由上游
探索决策/地图融合模块在发起规划前提供同义的目标 L0 证据窗。

飞跃式窗口一旦切到目标，在下一次飞跃目标到来前保持不变；模拟里程计更新不得把它重新移回
起点。轮式和足式窗口仍随模拟平台位置滚动。

## 5. 三维有限高度越障语义

全局栅格中每个普通障碍单元形成有限三维柱体：

```text
水平范围 = 完整栅格方形
底面高度 = elevation
顶面高度 = elevation + max(obstacle_height, global_resolution)
```

飞行管半径继续包含平台碰撞半径、地图裕量和着陆凸区域附加半径。对每个与飞行管水平投影
相交的栅格，计算该处飞行管下表面：

```text
lower_tube_z = 抛物线区间最低高度 - 对应横向偏移处的管体竖向半径
```

- `lower_tube_z` 高于障碍顶面：允许从上方飞越。
- 飞行管与障碍顶面相交：该候选抛物线失败；求解器可继续尝试更长飞行时间/更高弹道。
- 所有燃料和速度可行候选均碰撞：返回无已知安全飞行管，而不是把障碍当作落点问题。
- 地形本体使用 `elevation` 做连续飞行管碰撞检查；陨石坑由真实高程表达。
- 未知、过期或地图外飞行管不能认证。
- `forbidden` 继续按贯穿高度的禁入空域拒绝，避免在尚未拆分语义层时错误放行。

外部 Isaac/真实环境中的独立月岩碰撞体必须先栅格化到 `obstacle` 与
`obstacle_height`；规划器不能直接感知未进入地图的物理碰撞体。

## 6. 失败语义

| 条件 | 结果 |
|---|---|
| 目标支撑证据不在目标 L0 窗口内 | `LANDING_EVIDENCE_INSUFFICIENT` |
| RViz 桥没有 L0 源数据可切窗 | `LANDING_EVIDENCE_SOURCE_NOT_L0` |
| 目标窗更新参数缺失、非有限或非飞跃式会话 | `LANDING_EVIDENCE_TARGET_INVALID` |
| 目标支撑圆含普通障碍 | `HOPPER_LANDING_TARGET_OCCUPIED` |
| 候选飞行管碰到有限高度障碍 | `HOPPER_FLIGHT_TUBE_OBSTACLE_COLLISION` |
| 候选飞行管离开全局图 | `HOPPER_FLIGHT_TUBE_OUTSIDE_MAP` |
| 候选飞行管经过未知证据 | `HOPPER_FLIGHT_TUBE_UNKNOWN` |
| 候选飞行管进入禁入空域 | `HOPPER_FLIGHT_TUBE_FORBIDDEN` |

RViz 控制器在目标窗准备失败时不得发送 Action，并显示稳定的
`LANDING_EVIDENCE_PREPARATION_FAILED`，桥接器日志保留上表的具体原因。

## 7. 验证

### 7.1 主仓

- 保留并明确验证 20 m 跳跃面对 6 m 有限高度障碍时会选择更高可行抛物线。
- 增加“障碍高度超过所有可行弹道时不能认证”的反例，证明算法不是无条件忽略障碍。
- 验证精确目标支撑圆超出 L0 窗口时仍以 `LANDING_EVIDENCE_INSUFFICIENT` 失效关闭。
- 运行 Release `lunar_planner_core` 测试、仓库边界检查和 UTF-8/diff 检查。

### 7.2 外部 RViz 仓

- 参数原子更新只允许飞跃式目标窗，拒绝部分坐标、非有限值、非 L0 源和地图外目标。
- 飞跃式模拟里程计不得覆盖已经准备好的目标窗；轮式/足式仍随平台滚动。
- `refresh_generation()` 必须先准备目标窗，再调用 ready；准备失败不能发送 Action。
- 使用相距超过原 12 m 半径的起终点验证 Action 成功，`local_map` 覆盖目标支撑区域，RViz 同时
  显示完整全局障碍、有限高度越障弹道、飞行管和目标凸落区。
- 外部仓运行源码 pytest、ROS Release 构建/测试及现有启动 smoke。

## 8. 完成标准

1. 飞跃式 12 m 合成局部半径不再成为跳跃距离上限。
2. 任意距离目标只要全局飞行管可认证、燃料可达且目标附近存在 L0 安全证据，就可输出单跳。
3. 有限高度普通障碍可从上方穿越；飞行管相交的障碍仍被可靠拒绝。
4. 轮式、足式局部滚动行为和正式消息接口无回归。
5. 主仓变更合入 `integration`；外部验证工具变更独立合入其 `main`，不重新定基线旧 Isaac
   冻结快照。
