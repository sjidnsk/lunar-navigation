# Quad48 足式平台能力与规划设计

日期：2026-08-06
状态：已完成对话设计，等待书面规格审阅
目标分支：`legged-platform-capability-design`，通过资格检查后合入 `integration`

## 1. 目的与范围

本文冻结 Yobotics Quad48 在 `lunar_navigation` 中的足式平台实体参数、能力语义、分层规划、
连续碰撞认证、ROS 滚动执行和 RViz 证据要求。它取代现有测试代理中的足式假设，但不把
足式单平台资料误写成三平台正式能力冻结完成。

本文不设计落脚点、步态、关节轨迹或底层攀爬控制器。规划器只输出机身参考；实际步态、
跨沟和台阶技能由足式平台控制系统实现。

4. 用户确认的实机升级事实：图片中的 `0.16 m` 攀爬高度已经提升为 `0.50 m`；

外部路径只用于说明证据来源，不作为仓库运行时依赖。正式能力物料必须保存来源类型、版本、
摘要和审核记录，不能依赖以后会变化的 GitHub `main` 或本机路径。

### 2.2 来源类型

每个正式能力字段必须标记下列来源之一：

- `upstream_model`：从冻结提交的 URDF/MuJoCo 模型直接读取；
- `upstream_config`：从冻结提交的控制配置直接读取；
- `user_spec_material`：来自用户提供且已记录摘要的规格图片；
- `user_confirmed_upgrade`：用户确认的当前实机改造结果；
- `derived`：从已冻结几何或物理量计算；
- `planning_policy`：规划和执行层安全策略，不声称是实体极限。

来源冲突时不按数值大小自动选择。当前唯一明确覆盖旧资料的冲突是攀爬高度：
`user_confirmed_upgrade=0.50 m` 覆盖图片中的旧 `0.16 m`。

## 3. 平台实体与能力

### 3.1 几何、质量和执行器

| 字段 | 冻结值 | 来源 | 语义 |
|---|---:|---|---|
| 平台 | Yobotics Quad48 | `upstream_model` | 12 自由度四足平台 |
| 站立机身包络 | `0.68 × 0.33 × 0.35 m` | `user_spec_material` | 规划碰撞矩形和 RViz 真实比例的基础 |
| `base_link` 标称离地高度 | `0.33 m` | `derived` | 正常站立参考 |
| `base_link` 可用离地区间 | `[0.28, 0.38] m` | `planning_policy` | 机身参考允许区间 |
| URDF 总质量 | `15.89 kg` | `derived` | 工程显示可记为约 `16 kg` |
| 标称载荷 | 约 `8 kg` | `user_spec_material` | 元数据，不直接改变路径可行性 |
| 最大载荷 | `10 kg` | `user_spec_material` | 超过时能力文件失效，不能继续沿用原动态参数 |
| 产品关节峰值扭矩 | 约 `48 N·m` | `user_spec_material` | 实体规格记录 |
| URDF effort 限制 | `38 N·m` | `upstream_model` | 仿真模型关节限制 |

`config.yaml` 中的 `tau_limit: 200.0` 是控制软件配置值，不解释为 `200 N·m` 的真实关节能力，
也不覆盖产品规格或 URDF effort 限制。

### 3.2 运动能力

| 字段 | 冻结值 | 来源 | 规划用法 |
|---|---:|---|---|
| 前向物理峰值 | `4.0 m/s` | `user_spec_material` | 规格记录，不作为默认规划速度 |
| 前向额定速度 | `3.7 m/s` | `user_spec_material` | 规格记录 |
| 月面规划标称前进速度 | `1.5 m/s` | `planning_policy` | 平坦已知区域的默认上限 |
| 规划最大倒退速度 | `1.5 m/s` | `planning_policy` | 连续局部轨迹上限 |
| 规划最大横移速度 | `0.8 m/s` | `upstream_config`、`planning_policy` | 与保守遥控配置一致 |
| 最大偏航角速度 | `1.0 rad/s` | `upstream_config`、`planning_policy` | 连续局部轨迹上限 |
| 最大线加速度 | `1.0 m/s²` | `planning_policy` | 计时与局部轨迹约束 |
| 最大偏航角加速度 | `1.0 rad/s²` | `planning_policy` | 计时与局部轨迹约束 |
| 最大坡度 | `30°`，即约 `0.523599 rad` | `user_spec_material`、`derived` | 超过时硬拒绝 |
| 最大上下台阶高度 | `0.50 m` | `user_confirmed_upgrade` | `|Δh| ≤ 0.50 m` 为普通可行边 |
| 最大沟隙宽度 | `0.30 m` | `user_spec_material` | 沿实际运动方向测量无支撑跨度 |
| 台阶时间模型垂向速率 | `0.10 m/s` | `planning_policy` | 只估算执行时间，不是固定原语可达性门限 |
| 平面障碍安全净空 | `0.30 m` | `planning_policy` | 加在机身外形之外的规划策略 |

台阶和沟隙不是特殊 Action 或离散技能原语。满足硬约束时，它们与平坦移动一样是普通路径边；
规划器通过连续计时和降速表达难度，底层控制器自行调用对应技能。

`0.50 m` 台阶的垂向时间为 `5 s`，`0.30 m` 为 `3 s`，`0.10 m` 为 `1 s`。这些数值是
预计执行时间，不要求碰撞检查按时间密集采样，也不应令规划耗时随执行时长线性增长。

### 3.3 不属于物理能力的字段

- 粗糙度只进入诊断和 RViz 图层，不参与足式硬可行性、路径代价或速度缩放。
- 地图置信度属于独立运行时安全策略，不属于 Quad48 实体能力。
- 未知栅格是否通行属于地图策略；本设计固定为硬不可通行。
- 目标完成容差属于执行策略，不属于平台能力。

因此，正式足式能力结构不应继续使用 `maximum_roughness_m` 或 `minimum_confidence` 作为物理
能力门限。若 UI 需要粗糙度颜色范围，应放入独立可视化配置。

## 4. 地图与地形语义

全局层沿用项目已经批准的通用多分辨率规则，不按“50 m”或“1 km”写死地图尺寸。粗层负责
长距离拓扑搜索；所有将要执行的足式局部段都必须回到 `0.2 m` L0 地图完成认证。

地形规则如下：

1. 未知、越界、障碍和 forbidden 栅格硬拒绝。
2. 坡度超过 `30°` 硬拒绝；可行坡度通过速度模型影响预计时间。
3. 相邻地形高度差 `≤ 0.50 m` 时允许通过并按垂向时间计价。
4. 沟隙按运动方向上的实际无支撑长度测量，而不是简单计数横纵栅格；`≤ 0.30 m` 且沟隙
   两端支撑安全时允许通过，超过时硬拒绝。
5. 在 `0.2 m` L0 图上，一个完整无支撑栅格可能满足 `0.30 m` 上限，两个连续栅格形成的
   `0.40 m` 跨度必须拒绝；斜向跨越仍按米制长度判断。
6. 粗糙度变化不得改变上述结果。

探索候选点由外部探索决策网络拥有。候选点未知、碰撞或在已知空间内不可达时，规划器原样
拒绝并返回结构化原因，不吸附目标、不生成前沿点，也不自行选择替代候选。

## 5. 分层搜索架构

### 5.1 全局状态与完备性

足式全局搜索状态固定为 `(x, y)`，使用八邻接米制边。偏航不进入全局状态；这是降低长距离
搜索时间和内存的明确选择。

全局搜索不得因展开节点数、开放列表长度、候选数量或固定 wall-clock 预算达到阈值而报告
不可达。有限已知地图的开放列表真正耗尽后，才能返回 `NO_KNOWN_ROUTE`。以下情况必须区分为
“搜索未完成”：

- 外部取消；
- 外部截止时间到达；
- 内存分配失败或其他系统资源故障；
- 输入地图或能力版本在搜索期间失效。

碰撞采样数量由边的空间长度确定，不得以固定 subdivision 上限把一条可能可行边误判为物理
不可行。局部平滑优化可以有迭代上限，因为失败时仍可返回已认证的离散轨迹；这个上限不构成
全局搜索截断。

### 5.2 时间目标及其边界

全局层最小化不含偏航的预计执行时间下界：

```text
t_global_edge = max(d_xy / v_xy, |Δh| / 0.10, t_linear_accel)
```

局部层取得连续朝向后计算完整预计时间：

```text
t_edge = max(
  d_xy / v_xy,
  |Δh| / 0.10,
  |Δyaw| / 1.0,
  t_linear_accel,
  t_yaw_accel)
```

坡度、台阶和沟隙只通过可用速度或上述计时影响代价；粗糙度不进入公式。

纯 `(x,y)` 状态不能严格表示由上一条边方向决定的偏航代价。因此，本设计保证全局层最小化
平移/升降时间下界、局部层最小化该走廊中的偏航和平滑时间，但不声称结果是“包含偏航后的
数学严格全局最优”。若未来要求这一证明，必须另行批准带方向标签的多状态搜索，不能在本设计
中暗中恢复 yaw bins。

## 6. 三级碰撞筛选与局部认证

机身半长为 `0.34 m`，半宽为 `0.165 m`，安全净空为 `0.30 m`。由此得到：

```text
r_min = 0.165 + 0.30 = 0.465 m
r_max = hypot(0.34, 0.165) + 0.30 ≈ 0.678 m
```

全局中心净空按三类处理：

1. `< 0.465 m`：任何平面朝向都无法满足机身宽度和净空，直接拒绝；
2. `≥ 0.678 m`：任意平面朝向都能满足外接半径和净空，直接通过全局筛选；
3. `[0.465, 0.678) m`：条件可行，必须交给局部朝向与真实矩形碰撞认证。

局部认证使用旋转矩形与地图障碍的真实相交检查，禁止用旋转矩形的轴对齐包围盒或统一外接圆
代替。采样以机身中心平移加角点转动弧长计，连续样点间的最大扫掠距离不大于
`L0 resolution / 4 = 0.05 m`。轨迹平滑后必须重新执行同等或更严格的连续复检。

条件走廊认证失败时，只禁用导致失败的走廊或边并恢复全局搜索，不重建整张图，也不直接报告
目标不可达。

## 7. 局部朝向、平滑与轨迹语义

局部朝向采用自适应策略：

- 默认让机身前向轴沿路径切线；
- 狭窄区域允许利用 `0.8 m/s` 横移能力侧身通过；
- 任务有传感器朝向要求时允许保持任务朝向；
- 请求带显式目标 yaw 时，轨迹末端必须满足该 yaw；
- 联合降低转向量、朝向突变并保持碰撞净空。

局部输出语义固定为 `LEGGED_BODY_REFERENCE`，包含机身位置、姿态、速度和时间参考。不输出
足端接触序列、步态、关节命令或“攀爬/跨沟”技能命令。

优先输出经过平滑和复检的 `OPTIMIZED` 轨迹。若平滑未收敛，只能回退到已经完整认证的
`DISCRETE_FALLBACK`，并发布明确警告码；不能把回退结果显示为优化成功。

## 8. 起点、终点和目标容差

1. 轨迹第一个采样点必须等于本请求的新鲜真实 Odometry 位姿。
2. 不得把起点吸附到附近安全栅格，也不得忽略第一段碰撞。
3. 起点碰撞、未知、越界或无法连续连接时，返回对应结构化错误。
4. 局部轨迹必须连接 RViz 或上游请求给出的连续 `(x,y)` 目标；不得以邻近目标栅格替代。
5. 请求带目标 yaw 时必须连接该 yaw；未带 yaw 时由局部自适应朝向决定。
6. 规划目标区域不因失败自动扩大。
7. Action 执行完成容差与规划分离，默认位置 `0.05 m`、偏航 `5°`；它只判定执行完成，
   不参与搜索或改变规划终点。

零执行容差不适用于带里程计噪声的实际系统。

## 9. ROS Action 与滚动执行

同一规划请求必须绑定：

- 全局地图版本和 L0 局部地图版本；
- 当前平台与能力版本/摘要；
- 新鲜 Odometry；
- 探索决策网络提供的原始目标；
- 运行时地图安全策略。

成功结果包含完整全局路线预览和当前唯一授权的 L0 局部段。完整路线用于引导和显示，不代表
全部获得执行授权。

足式执行反馈固定使用：

- `plan_id = segment_id = MotionReference.plan_id`；
- 状态 `SEGMENT_COMPLETE`；
- 与该段身份匹配且时间更新的 Odometry。

三者一致后，滚动协调器推进 route cursor，并从真实状态认证和授权下一段。执行偏离、地图或
能力版本变化、局部认证失败时，旧 continuation 失效并重新规划。RViz 提交新地面目标时可以
安全替换当前足式滚动会话，但迟到的旧反馈不能激活新段。

## 10. 结构化结果与错误

至少保留下列稳定语义：

- `GOAL_UNKNOWN`：目标处没有可用地图证据；
- `GOAL_COLLISION`：目标机身包络和安全净空不满足；
- `START_UNKNOWN`、`START_COLLISION`、`START_CONNECTOR_INFEASIBLE`；
- `NO_KNOWN_ROUTE`：有限已知地图确实搜索穷尽；
- `LOCAL_CORRIDOR_INFEASIBLE`：当前候选走廊失败，搜索仍可继续时不得作为最终无路；
- `REQUEST_CANCELED`、`SEARCH_DEADLINE_EXCEEDED`、`SEARCH_RESOURCE_FAILURE`：搜索未完成；
- `MAP_VERSION_CHANGED`、`CAPABILITY_VERSION_CHANGED`：请求证据失效；
- `OPTIMIZED`、`DISCRETE_FALLBACK`：轨迹生成模式。

探索决策网络根据上述目标/路线错误选择下一候选；规划器不修改外部候选点。

## 11. Isaac Sim 与 RViz 表达

Isaac Sim 使用冻结 URDF 转换得到的完整关节模型，并为各物理连杆保留独立碰撞体。规划层
使用参数化机身矩形，两者职责不同；规划代理不能替代 Isaac 关节碰撞验证。

RViz 必须：

- 只显示当前选择的足式平台；
- 以真实 `0.68 × 0.33 m` 平面比例显示平台 Marker，并随 Odometry 移动；
- 用不同符号区分真实起点、精确目标和平台实体；
- 显示完整全局障碍，局部 L0 危险区域另行高亮；
- 用细线显示全局路线，用高亮粗线显示当前授权段；
- 显示 `OPTIMIZED`/`DISCRETE_FALLBACK`、碰撞认证状态、位置/偏航容差和原因码；
- 不重新实现碰撞判定，只显示规划器和冻结地图提供的证据。

## 12. 验证与通过标准

### 12.1 能力与来源

- 校验上游提交、相关文件摘要和本地规格图片摘要；
- 验证 `0.16 m` 不再出现在正式足式能力输出；
- 验证 `tau_limit: 200.0` 不会转换成真实 `200 N·m` 能力；
- 验证测试代理能力不能解除正式训练门禁。

### 12.2 核心算法

- 坡度 `30°`、台阶 `0.50 m` 和沟隙 `0.30 m` 的边界内外正反例；
- 斜向沟隙按米制跨度而非栅格数量判定；
- 改变粗糙度不改变足式可行性、代价和速度；
- 未知栅格和未知目标硬拒绝；
- `0.465 m`、`0.678 m` 三级净空边界测试；
- 旋转矩形可通过但外接圆不可通过的窄通道正例；
- 轴对齐包围盒会误拒绝、真实旋转矩形应通过的回归；
- 横移、保持任务朝向和显式目标 yaw；
- 精确真实起点和连续终点连接；
- 平滑后碰撞复检，以及明确的离散回退状态；
- 全局搜索穷尽与取消/截止时间/资源失败的状态区分；
- 不存在固定展开数、开放列表或候选数导致的假不可达。

### 12.3 ROS、滚动和 RViz

- 首个认证段完成后，身份匹配反馈与新鲜 Odometry 自动触发下一段；
- 迟到、重复、错误身份和旧地图版本的反馈不能推进 route cursor；
- 新目标安全替换足式会话；
- RViz 同时显示真实平台、全局路线、当前授权段、全局障碍和结构化状态；
- 同一地图和同一请求贯穿 C++ 核心、ROS Action、外部桥和 RViz，不接受各层使用不同世界的
  “分别通过”。

所有性能回归强制使用 Release。除固定 50 m 合成图回归外，还要覆盖通用多分辨率长距离图，
记录地图尺寸、分辨率层级、展开数、规划 p50/p95、峰值内存和结果摘要；门槛必须在实施计划中
依据当前 Release 基线冻结，不能通过重新加入搜索截断来达标。

## 13. 与现有实现的预期差异

后续实施计划需要处理以下已知差异，但本文不执行代码修改：

1. 当前足式全局状态仍包含 yaw bin，需改为 `(x,y)` 并把朝向延迟到局部走廊。
2. 当前粗糙度会触发硬拒绝和代价，需从足式物理判定和计价路径移除。
3. 当前 `minimum_confidence` 位于物理能力结构，需迁移到独立地图安全策略。
4. 当前 `maximum_gap_width_m` 只加载和校验，需实现沿运动方向的实际无支撑跨度判定。
5. 当前固定时长原语与垂向速率组合会误拒绝 `0.50 m` 台阶，需改为普通边和连续时间模型。
6. 当前足式扫掠使用旋转矩形的轴对齐包围范围，需改为真实旋转矩形相交。
7. 当前部分 subdivision、候选和搜索资源配置可能产生假不可达，需按本设计区分物理不可行与
   搜索未完成。
8. 当前测试/代理能力资料不得原地改名为正式 Quad48 能力；正式资料必须带独立来源记录。

## 14. 训练门禁与非目标

完成本文只代表足式平台正式能力设计冻结。正式 PPO 训练仍必须依次具备真实轮式、足式和
飞跃式能力资料，生成并校验三平台 capability freeze，重建平台化可通行性/候选缓存并冻结
worker 与 micro-batch 后才能启动。本文不启动训练、ONNX、TensorRT 或 AGX 发布。

本文也不改变外部探索决策网络、地图融合系统、足式底层控制器或上游 ROS 消息的所有权。
