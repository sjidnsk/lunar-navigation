外部 capability closure、URDF 或 mesh 才能进入训练的表述由

具有权威。飞跃式参考推进剂只用于固定单跳 `delta-v` 包线，不进入探索状态且不会跨跳扣减。

## 背景与已批准结论

用户提供的《多模态传感器架构_v3.xlsx》描述了多模态感知系统使用的 RGB、SWIR、事件相机、激光雷达、ToF 和 IMU 等设备。本项目不复现多模态融合、目标识别、辐射特性或具体传感器成像过程，只建立一个保守、确定且计算高效的几何观测抽象，用于闭合探索候选、PPO 决策、规划执行和实际覆盖奖励。

正式探索能力固定为：

```text
sensor_range_m = 30.0
sensor_fov_deg = 360.0
```

这是一项系统级地形和物理障碍观测能力，不表示每个传感器都能在 30 m、360° 条件下独立工作，也不表示系统能在该范围内完成科学目标识别。三类平台在当前设计中共享同一套传感器系统观测能力；平台运动差异仍由各自 capability、可通行投影和 C++ v3 规划结果表达。

## 设备依据与保守偏差

表中的 Ouster OS1 Rev7 提供 360° 水平视场，是系统级水平 FOV 的依据。表中暗目标和亮目标标称探测距离分别为 90 m 和 170 m；采用 30 m 后：

- 相对 90 m 缩短 60 m，即保守 66.7%；
- 相对 170 m 缩短 140 m，即保守 82.4%。

Basler blaze ToF 的表中范围约为 10 m，因此 30 m 不能解释成 ToF 单独能力。RGB、SWIR 和事件相机用于系统多模态输入，但它们的窄视场、光照响应和识别距离不扩张本设计的几何能力。IMU 不产生环境覆盖范围。

因此，30 m/360° 只是一项由 360° 激光雷达支撑、对其标称距离显著降额的系统聚合能力。月球极区光照差异不再额外缩短这个几何范围；若后续实测或上游融合系统给出更保守的有效范围，必须形成新的 capability 版本并重新训练、评估和发布模型。

## 范围与非目标

本设计包括：

- 训练环境中的候选信息增益估算；
- 执行后的真实可见区域更新；
- 与现有 `valid_mask`、`observation_age_s`、`observation_quality` 和 `observation_count` 语义闭合；
- 高效、确定的批量视线计算；
- 360° FOV 下三平台 `theta` 动作的正确训练语义；
- capability 冻结、性能门和回归测试。

本设计不包括：

- 多传感器时间同步、标定、融合和故障诊断；
- 光照、反射率、噪声、点云密度或识别概率仿真；
- 飞跃过程中的在线观测；
- 外部感知系统拥有的真实地图生成逻辑；
- 重定基线旧 Isaac/ROS 验证快照。

2026-08-03 Isaac/ROS 历史设计中的 `30 m/120°` 继续只作为当时冻结的实验记录，不修改原文，也不能作为正式 PPO 训练的传感器能力来源。

## 权威数据边界

系统必须区分三类数据：

1. **世界真值**：仅由训练场景或仿真环境持有，用于模拟一次真实观测的结果；策略、候选生成器和规划器不得直接访问。
2. **已观测世界**：由真实外部地图或训练观测更新器产生，包含策略和规划器可以使用的有限知识。
3. **任务栅格**：包含 ROI、优先级和 `forbidden` 等任务语义；它不代表传感器可见性。

网络观测构造器只接受 `ObservedWorld`。正式训练中任何从真值直接构造网络通道、候选特征、candidate mask 或奖励预测的路径都属于真值泄漏，必须使运行失败。

30 m 只用于候选点的信息增益估算和一次实际观测的几何上限。它不能自动把机器人周围圆形区域设为已知。某个单元是否可供规划使用，仍由地图中的 `valid_mask`、`observation_age_s`、`observation_quality`、`observation_count` 以及现有安全阈值共同决定。

## 可见性语义

### 共同几何规则

- 距离按源单元中心与目标单元中心的平面欧氏距离计算，只有距离不大于 30 m 的单元才可参与。
- 正式 FOV 为 360°，因此可见性与机器人 yaw、候选 bearing 和策略 `theta` 无关；实现走无三角函数的 360° 快路径。
- 栅格射线沿用当前候选生成器的确定性 Bresenham 单元序列，端点、行列顺序和并列处理必须与慢速 Python 参考完全一致。
- `obstacle`/物理障碍层中任意大于零的占据比例都会遮挡视线。射线上的第一个物理障碍单元自身可见，其后的单元不可见。
- `forbidden` 是任务禁入语义，不是实体，不遮挡视线。
- 当前模型不另建垂直 FOV、地形地平线和光照衰减模型；月岩、陨石坑壁等需要遮挡的实体必须进入物理障碍层。

### 候选信息增益估算

候选估算严格只读取已观测世界：

1. 候选点必须位于已观测、当前平台可通行的单元，且不得是机器人当前所在的全局栅格；从机器人当前位置到候选点的路径预筛仍使用现有 observed-only LOS 和 C++ v3 快速投影。当前位置不代表探索进展，不能以零位移动作进入策略或规划器。
2. 对每条候选射线，所有中间单元必须已经观测且无物理障碍。
3. 只有紧邻这段已知自由视线的第一个未知端点可以计入潜在增益；不得穿过未知单元估计其后区域。
4. 普通增益和优先增益继续按 `roi_ratio` 的物理面积权重累计，不按栅格个数替代面积。
5. 30 m 不改变固定 64 候选合同；不能通过减少候选数规避性能门。

这项估算只用于排序候选和构造特征，不改变 `observed_mask`，也不直接产生覆盖奖励。

### 实际观测更新

训练环境在允许的决策边界调用一次真值可见性更新：

1. 从平台真实位置向 30 m 圆内目标单元发射同一套 Bresenham 射线；
2. 射线可以穿过真值中的自由单元，并持续揭示这些单元；
3. 揭示并终止于第一个真值物理障碍，障碍后的单元保持未知；
4. 可见单元的地形和物理障碍内容从场景真值复制到已观测世界；
5. 新观测单元设置 `valid_mask=1`、`observation_age_s=0`、`observation_quality=1.0`，复制训练场景明确提供的高程/障碍不确定度，并将 `observation_count` 按其整数类型上限饱和递增；这里的 `1.0` 仅表示训练抽象在保守 30 m 范围内成功返回一次有效几何观测，不是对真实融合质量的声明；
6. 未再次观测的已知单元保留原内容，`observation_age_s` 按实际宏步时间增加；
7. 重复观测不能再次产生新增覆盖奖励。

训练更新器只是确定性的传感器抽象。部署时这些字段继续由外部传感与融合系统拥有，本项目不得用训练更新器替代真实地图来源。

## 探索训练闭环

每个宏步固定为：

```text
训练真值
  -> 已观测世界
  -> 批量候选可见性估算
  -> 七项 PPO 输入
  -> 候选位置与 theta 动作
  -> C++ v3 规划和认证
  -> 执行到下一决策边界
  -> 单次真实可见性更新
  -> 实际新增覆盖奖励与下一观测
```

轮式和足式平台在滚动执行的探索决策边界更新观测；规划内部的局部段切换不自动触发新的 PPO 动作。飞跃式平台在已承诺和飞行期间不更新观测、不请求新动作，只在稳定进入 `LANDED_HOLD` 后执行一次观测更新并进入下一宏步。

每个回合在第一次构造候选前还必须从初始真实位姿执行一次观测更新；初始观测不计作执行动作，也不产生动作奖励。

奖励中的 `mission_observed_delta` 和 `priority_observed_delta` 必须来自实际新揭示的物理面积。候选阶段的 30 m 潜在增益不得直接当作奖励，也不得提前写入覆盖统计。

## 高效实现架构

### C++ 批量可见性内核

沿用现有 Python `_ray_cells()` 和 `_clear_observed()` 作为可读的权威参考，实现共享的 Release C++ 可见性内核。内核提供两个单一职责入口：

- `EstimateCandidateGains`：一次接收当前轮全部待评估候选、已观测掩码、物理障碍、ROI 和优先级，批量返回普通增益与优先增益；几何选择完成后的公开输出仍严格限制为 64 项；
- `RevealFromPose`：接收一个实际平台位置和训练真值，返回本次可见掩码，由环境层负责更新 `ObservedWorld`。

实现要求：

- 以 `(resolution_m, range_m)` 为键预计算圆形偏移和确定性射线模板；
- 30 m 范围内只遍历模板单元，不再对每个候选扫描完整 `256 x 256` 全局画布；
- 64 个候选在一次原生调用中完成，避免 Python/C++ 往返；
- Python 绑定在计算期间释放 GIL；
- 内核内部保持单线程，不启用 OpenMP，避免 18/24 worker 场景嵌套扩线程；
- 输出按固定 row-major 和候选稳定索引排序；
- 不使用 GPU，避免小型离散任务的传输和调度开销；
- 正式训练、基准和发布构建强制使用 Release。

候选位置和网络全局输入继续使用固定 `1024 m @ 4 m/cell = 256 x 256` 画布，但候选信息增益从机器人当前持有的稀疏 `0.2 m` 已观测状态计算。实现只拼接覆盖本批候选 30 m 视域的最小联合窗口；64 候选的最坏资格 fixture 为 `601 x 601 @ 0.2 m`。原生核先一次提取紧邻已知自由区的未知边界，再批量检查各候选射线，禁止为每个候选重复扫描完整高分辨率窗口。Release 基准仍须满足候选批次 p95 不高于 5 ms。

### 能力注入

生产候选生成器不得保留当前 `80 m/360°` 默认参数。正式入口必须从仓库内项目正式能力适配器
注入 capability v2 与 `30 m/360°` 观测语义，并将两者摘要写入运行身份。缺失参数、范围/FOV
非有限、FOV 超界、仓库批准能力摘要漂移或 checkpoint 与运行能力不一致均 fail closed；正式
入口不接受可替换这一权威的外部 capability lock。

正式训练 manifest、checkpoint、评估报告和最终四文件模型包必须记录同一观测 capability 标识与内容哈希。改变 30 m、360°、遮挡规则或观测边界语义后，旧 checkpoint 不得继续训练，旧模型不得直接重新发布；必须重新生成候选缓存并重新训练和资格评估。

## 360° FOV 与 theta 动作

`theta` 的冻结语义是“到达所选候选后的绝对 `map` 机体 yaw”，不是传感器观看方向。360° FOV 会使即时观测增益对 `theta` 不变，但不会消除所有平台的运动学训练信号。

- **轮式**：`theta` 参与终端 yaw、转向、路径长度和执行时间，保留完整训练信号。
- **足式**：`theta` 参与终端 yaw 和偏航时间，信号通常弱于轮式但仍有实际意义。
- **飞跃式**：当前项目只选择安全且抛物线可达的着陆区域，飞行控制由外部单位负责；360° 观测下着陆覆盖主要由位置决定，不应靠人为姿态时间训练一个无任务意义的 yaw。

不修改现有四输出合同：

```text
frontier_logits
theta_mu
theta_kappa
value
```

训练和运行时从已经验证的 `platform_context` 派生内部 `theta_action_mask`：

```text
WHEELED = true
LEGGED  = true
HOPPER  = false
```

联合动作概率使用：

```text
log_prob_total = log_prob_frontier + theta_action_mask * log_prob_theta
```

`theta` 熵只对 active 行求平均；一个 batch 没有 active 行时该项精确为零。旧、新策略计算必须使用相同 mask。飞跃式仍输出固定 shape 的 `theta_mu/theta_kappa`，但适配器忽略它们，并以 `goal.yaw_rad=nullopt` 调用飞跃规划器，使其保持当前 yaw。共享骨干仍通过飞跃式的候选、价值和平台上下文训练，不增加平台专用 head、checkpoint 或 ONNX 输出。

四输出 `ActionContractV2` 的 shape 和名称保持不变，但 PPO 联合概率语义、动作适配语义及其训练配置标识必须升级并进入 checkpoint/manifest 哈希。采用旧 joint-log-prob 语义的 rollout 或 checkpoint 不能与本设计续跑。

不得人为缩小 FOV 来制造 `theta` 的覆盖奖励。未来只有在外部飞跃控制能力明确提出着陆 yaw 约束并给出可验证代价后，才能发布新 capability 版本并重新启用飞跃式 `theta`。

## 错误处理

- 单个候选越界、位于未知/不可通行单元或 observed-only LOS 不成立时，仅将该候选置为无效；不足 64 项继续零填充并置 mask。
- 平台实际位置越界、真值与已观测地图几何不一致、层类型/shape 非法、能力缺失或 hash 漂移属于基础设施错误；该 rollout 不得进入 PPO，正式训练必须停止而不是转成普通负奖励。
- 候选全部无效时沿用现有 all-false bypass 语义，不调用策略，也不伪造当前位置候选。
- C++ 内核异常、非有限增益、非确定输出或 Python 参考不一致均 fail closed。
- 真值对象不得出现在网络观测构造器、候选接口或生产 ROS 节点的公开类型中。

## 验证与性能门

### 正确性测试

1. 对随机小图、边界图、单障碍、连续障碍和多射线并列情形，C++ 可见掩码与慢速 Python Bresenham 参考逐单元完全一致。
2. 候选估算不得穿过未知单元或已知物理障碍，且不得读取真值；实际 reveal 可穿过真值自由单元，显示第一个障碍并遮住其后区域。
3. `forbidden` 不遮挡，物理障碍遮挡；重复观测不增加覆盖。
4. 相同位置、不同 yaw/`theta` 在 360° 模式下产生完全相同的候选增益和实际可见掩码。
5. 网络构造器继续拒绝真值类型，并只从实际已观测状态构造七项输入。
6. 轮式和足式的不同 `theta` 能进入 yaw 约束并影响可行性、代价或下一状态；飞跃式不同 `theta` 不改变规划请求和落点认证。
7. 混合平台 PPO batch 中，飞跃式 `theta` 不进入 joint ratio、KL 或 theta entropy；轮式和足式梯度保持有限且非零。
8. 初始观测、地面决策边界和 `LANDED_HOLD` 观测时机符合宏步合同，飞行中不得更新。
9. 能力缺失、非法值、hash 不匹配和 checkpoint 漂移均被拒绝。
10. 冻结的 yaw-sensitive 地面场景必须证明同一候选位置的不同 `theta` 会产生可学习的规划代价、耗时或下一状态差异；训练评估同时报告轮式/足式 `theta` 分布及固定 yaw 反事实诊断，避免把随机收敛误报为朝向选择能力。

### 正式训练性能门

在正式 Ubuntu 22.04 amd64 训练主机、Release 构建、正式 24-worker 配置下：

- `256 x 256`、64 候选批量增益估算 p95 不高于 5 ms；
- 单次 `0.2 m` 分辨率、30 m 半径实际 reveal p95 不高于 2 ms；
- 启用完整观测更新后，24-worker 端到端采样吞吐相对禁用观测更新的同场景基线下降不超过 10%；
- 所有离散输出与慢速参考完全一致，面积累计只允许既定浮点容差；
- benchmark 记录 Release 标识、主机、编译器、worker 数、场景 seed、预热次数、样本数和 p50/p95。

任一性能门失败都阻止正式 24 小时训练。不得通过降低候选数、缩小地图、跳过实际 reveal 或放宽正确性来通过门槛；只能优化模板、内存布局、批量边界和常数开销，或在记录证据后使用已批准的 18-worker 回退配置重新资格评估。

## 实施边界与完成标准

本规格应先进入 `integration`。训练实现依赖当前 Volume 3 策略流水线材料；在实现合入前，必须按仓库分支规则把所需的已资格代码带入基于 `integration` 的功能分支，不能继续推进 `volume-3-policy-pipeline` 里程碑分支，也不能把外部仓 artifact 导入本仓。

部署侧继续只消费外部传感与融合系统发布的地图。本仓实现候选估算、训练 reveal 抽象、PPO
`theta` mask、项目正式能力哈希校验和回归门，不取得真实传感器数据所有权。未来外部感知系统
若发布新的 observation capability，只能通过新的项目 capability 版本显式评审和切换，不能在
运行时静默覆盖本轮训练身份。

完成标准为：

- 30 m/360° 能力有唯一版本和稳定哈希；
- 候选估算、实际观测和奖励闭环不存在真值泄漏；
- C++ 批量内核通过正确性与性能门；
- 三平台 `theta` 语义和 PPO 损失与本设计一致；
- 旧 Isaac 快照保持历史状态；
- 正式训练开始前重新生成平台化候选缓存，并把观测能力哈希写入训练与模型发布证据。
